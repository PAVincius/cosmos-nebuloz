**Status:** Approved

## Overview

Upgrade the cosmos-nebuloz SAFe Copilot to match the Iris project's chat experience. Iris (`/Github/iris`) is a full-featured AI chat app with thread history, code syntax highlighting, RAG source display, follow-up suggestions, message actions, streaming animation, response feedback, and image attachment previews. Cosmos already has the hard infrastructure (SSE streaming, role-aware context, Prisma sessions, TipTap editor) — this spec covers porting the UI layer from Iris and wiring it to existing cosmos internals.

---

## Layout: Option C — Both Modes

Two co-existing entry points to the same session:

### 1. Right Drawer (in-context)
- Opens from the existing floating action button (FAB) or Cmd+K
- 340px wide, slides in from the right over page content
- Same message thread, compact density
- "Full page ⛶" button in header → navigates to `/copilot/[sessionId]`
- Replaces/upgrades existing `copilot-panel.tsx`

### 2. Full-Page (`/copilot/[sessionId]`)
- Dedicated route alongside the existing app layout
- Left sidebar (220px): thread history with time grouping + pin/unpin/rename/delete
- Main area: full-density chat with all features
- FAB navigates here when `sessionId` is known; creates new session when not

Both modes share the same session and render the same components — only density and container differ.

## Architecture

### New Route

```
apps/app/app/(authenticated)/copilot/[sessionId]/page.tsx
```

Dynamic route. Loads session via `loadCopilotSession(sessionId)`. Redirects to new session if `sessionId` is `"new"`.

All located in `apps/app/app/(authenticated)/components/copilot/`:

| File | Purpose |
|------|---------|

| `copilot-thread-sidebar.tsx` | History list, time-grouped, search input |

### Prisma Schema Additions

Three fields on `CopilotSession`, four on `CopilotMessage`:

```prisma
model CopilotSession {
  // ... existing fields ...
  pinned      Boolean   @default(false)
  pinnedAt    DateTime?
  title       String?
}

model CopilotMessage {
  // ... existing fields ...
  sources      Json?    // Array<{ title: string; url: string; snippet: string; icon?: string }>
  suggestions  Json?    // string[]  (2–3 follow-up question strings)
  feedback     Int?     // 1 = thumbs up, -1 = thumbs down
  feedbackNote String?
}
```

Single migration: `pnpm migrate`.

### New Server Actions

File: `apps/app/app/actions/safe-copilot/sessions.ts` (extend existing):

| Action | Signature |
|--------|-----------|
| `listCopilotSessions` | `(surface?: string) → CopilotSession[]` sorted by `pinnedAt DESC, createdAt DESC` |
| `renameSession` | `(id: string, title: string) → void` |
| `pinSession` | `(id: string) → void` sets `pinned=true, pinnedAt=now` |
| `unpinSession` | `(id: string) → void` clears `pinned, pinnedAt` |
| `deleteSession` | `(id: string) → void` cascades messages |
| `saveFeedback` | `(messageId: string, rating: 1 \| -1, note?: string) → void` |

### SSE Stream Additions

`/api/copilot/chat/route.ts` emits two new event types after the answer tokens end:

```ts
// After streamText completes:
emit('sources', chunks.map(c => ({ title: c.title, url: c.url, snippet: c.text, icon: c.favicon })))
emit('suggestions', ['...', '...', '...'])  // generated via parallel generateObject() call that starts after RAG retrieval, resolves after main stream ends
```

`use-copilot-chat.ts` already handles `applyChunk` — extend to handle `sources` and `suggestions` chunk types, storing them on the message object.

### State Additions

**`useCopilotSessions` hook** (new file):
- Loads session list via `listCopilotSessions`
- Optimistic pin/unpin/rename/delete
- Groups sessions by time bucket for sidebar rendering

**`CopilotProvider` additions:**
- `sessionId: string | null` — current active session
- `openDrawer(sessionId?)` — opens drawer, optionally switching session
- `openFullPage(sessionId?)` — navigates to `/copilot/[sessionId]`
- `createSession()` — calls `createCopilotSession`, updates `sessionId`

## Data Flow

```
User types → TipTap editor → useCopilotChat.submit()
  → POST /api/copilot/chat (sessionId, message, history, role)
  → Server: RAG retrieval → buildPrompt → streamText (Anthropic)
  → SSE stream:
      text-delta chunks → applyChunk → live text render (RAF animation)
      sources event     → message.sources → CopilotSourceStrip
      suggestions event → message.suggestions → CopilotFollowupChips
  → Stream end: persist full message to DB (CopilotMessage)
  → Feedback click → saveFeedback() → CopilotMessage.feedback
```

Thread navigation:
```
Sidebar click → router.push(/copilot/[sessionId])
  → loadCopilotSession(sessionId) → messages hydrated into useCopilotChat
```

## Error Handling

- Stream error event → display inline error in message bubble (existing behavior, unchanged)
- `saveFeedback` failure → silent retry once, then ignore (feedback is non-critical)
- `deleteSession` → optimistic remove from sidebar; rollback on error with toast
- Image too large (>5MB) → inline error below dropzone, no upload
- Session not found → redirect to `/copilot/new`

## Out of Scope

- Voice input / TTS
- Offline / IndexedDB fallback (cosmos uses server DB, not local)
- Settings modal (model selection stays in existing settings, not replicated inside copilot)
- Credit display (cosmos uses quota system, not credit UI)
- Command search across threads (Cmd+K already opens copilot; full search is a future story)
- MCP tool settings panel

4. New `/copilot/[sessionId]` route is additive — FAB updated to navigate there
