## Como o k6 chama a Server Action (T007)

Confirmado empiricamente contra este mesmo build — Chromium real
(`claude-in-chrome`), `fetch` patchado na página antes de disparar
`saveDraft` de verdade:

- **Método**: POST pro próprio path da página (`/meridian-responder/<token>`), não um endpoint separado.
- **Headers**: `Accept: text/x-component`, `Next-Action: <id resolvido do manifest>`. `next-router-state-tree` (que o Next.js manda) **não é necessário** — testei sem ele (fetch direto no console) e o servidor respondeu 200 com o resultado correto da action. Content-Type não precisa ser setado à mão (browser usa `text/plain;charset=UTF-8` pra body string por padrão); o k6 seta explicitamente pra ficar claro.
- **Corpo**: string JSON do array de argumentos da action — pra `saveDraft`, `[{"token":"...","answers":[...]}]`.
- **Resposta**: stream Flight (`text/x-component`), mas o resultado do `Result<T>` do `safeAction` aparece dentro como `{"ok":true,"data":...}` — dá pra checar sucesso com `body.indexOf('"ok":true')`, sem parsear o Flight de verdade.
- **IDs de action**: resolvidos de `.next/server/server-reference-manifest.json` (`node[id].workers[route].exportedName`) no topo do script — `saveDraft` deste build: `40abb3c8f42716e772ea4fca598a16e8ffc2320e0c` (muda a cada build, por isso não hardcoded fora da resolução).

## Resultado (T008) — 2026-09-27, contra `next build`/`next start` local, `cosmos-dev` (5434)

10 VUs consultores + 30 VUs respondentes, 30s cada, 35s total. **0% erro nos dois cenários**, bem abaixo do critério do SC-011 (hipótese: p95 < 2s, erro < 1%):

| Cenário | Requisições | p90 | p95 | max | erro |
|---|---|---|---|---|---|
| **consultores** (GET carteira + GET detalhe) | 1.400 | 264.8ms | **278.7ms** | 672.1ms | 0.00% |
| **respondentes** (GET bateria + 2× POST saveDraft) | 6.465 | 186.5ms | **198.4ms** | 553.1ms | 0.00% |

Total: 7.866 requisições HTTP, 2.855 iterações, 222.6 req/s, 0 falhas de threshold.

**Leitura**: números muito abaixo do critério — carga sintética local (200 respondentes, DB local sem latência de rede real, sem os outros produtos competindo por recursos) não é o mesmo que concorrência real de produção. Serve como primeiro sinal de que a Server Action `saveDraft` não tem um gargalo óbvio sob essa escala, não como prova de que o SC-011 (hipótese de "centenas de usuários por tenant") está cumprido — esse número ainda não foi validado com os leads (T009, em andamento, `roteiro-concorrencia-leads.md`).
